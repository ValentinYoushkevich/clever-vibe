# Clever Vibe

Сервис фиксации результатов применения ИИ-ассистентов во Frontend-разработке.

## Зачем

Внутренний инструмент на время пилота по внедрению ИИ-ассистентов (команда — тимлид + 3 разработчика, проект на Angular, React или Vue, срок до 3 месяцев). Разработчик за 20–30 секунд отмечает каждое применение ИИ прямо по ходу работы, а команда получает сводную картину: какие подходы реально дают эффект, а какие нет.

Сервис **не оценивает разработчиков**. Персональные срезы нужны только чтобы человек подготовил свою сводку к ежемесячной встрече; в общекомандных представлениях авторство записей не раскрывается.

## Что считается записью

Одно применение подхода, а не задача: на одной задаче может быть три записи — сгенерировал компонент, сгенерировал тесты, прогнал свой PR через ИИ. Ожидаемый объём за пилот — 300–600 записей.

## Какие метрики собираются

С каждой записи снимаются:

- **стадия** работы (анализ, проектирование, код, рефакторинг, дебаг, тесты, ревью, документация, прочее);
- **подход** из справочника (~41 вариант, привязан к стадии); свободный ввод названия запрещён — вместо него «другой подход» со свободным текстом, который лид разбирает и при повторяемости добавляет в справочник;
- **инструмент** из справочника утверждённых;
- **польза** (usefulness) — 1–5: от «помешало, потратил время впустую» до «сэкономило часы»;
- **доверие к результату** (trust) — 1–5: от «выкинул полностью» до «взял как есть»;
- ключ задачи и свободная заметка — опционально.

На их основе считаются агрегаты:

- средняя польза и среднее доверие по подходу, частота применения (N) и охват (сколько участников из команды);
- квадранты «частота × польза»: размер точки — число записей, цвет — среднее доверие;
- покрытие стадий — где ИИ применяют, а где нет;
- динамика средней пользы по дням / неделям / месяцам / за весь пилот;
- разброс между участниками — отрезок min–max их средних оценок по подходу;
- личная сводка за месяц (стадия → подход → N, средние, свои заметки).

Везде рядом со средней показывается N, а при N < 5 значение приглушается и помечается «мало данных». Выгрузка всех записей в CSV — для итогового отчёта.

## Роли

`dev` — вносит записи и видит свои; `lead` — плюс справочник подходов, участники своей команды, экспорт; `admin` — техническая роль, заводит лидов и наблюдателей, удаляет участников; `observer` — только дашборд и экспорт.

## Технологии

- **Бэкенд:** Node.js 22, Fastify 5, Prisma 6, PostgreSQL, TypeScript (ESM)
- **Фронтенд:** Vue 3 (Composition API), Vite, PrimeVue 4, Tailwind 4, Pinia, vue-router
- **Тесты:** Vitest (сервер — через `app.inject()`, веб — компонентные)
- **Оформление:** три темы (`nocturne`, `black`, `mint`) на CSS-переменных, переключение атрибутом `data-theme`; иконки PrimeIcons; шрифт Inter локально
- **Развёртывание:** Docker → Northflank (два сервиса: API и статика за nginx), БД — Neon; миграции применяются отдельным шагом, не при старте приложения
- **Репозиторий:** монорепо на npm workspaces — `server/` и `web/`

Авторизация — логин и пароль из БД, связка хранится в localStorage, автовход при следующем заходе. Сессий и JWT нет: 4 участника, внутренний контур.

## Локальный запуск

```bash
npm install
npm run dev      # server :3000 + web :5173
npm test         # тесты обоих пакетов
npm run build
```

Нужен PostgreSQL и `server/.env` с `DATABASE_URL`, `DIRECT_URL`, `ADMIN_NAME`, `ADMIN_LOGIN`, `ADMIN_PASSWORD` (см. `server/.env.example`). Первичное наполнение — `npx prisma migrate deploy && npx prisma db seed` из каталога `server/`.

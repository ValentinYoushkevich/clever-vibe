# Handoff: Clever Vibe — сервис фиксации результатов применения ИИ-ассистентов

## Overview
Clever Vibe накапливает факты применения ИИ-инструментов в ходе разработки (одна запись = одно применение подхода) и даёт сводную картину: какие подходы дают эффект, а какие нет. Пилот — 1 Team Lead + 3 разработчика, Angular-проект, до 3 месяцев, ориентировочно 300–600 записей. Сервис не оценивает разработчиков: персональные срезы нужны только для того, чтобы человек сам подготовил сводку к ежемесячной встрече.

Пять экранов: **Вход**, **Быстрый ввод** (главный, три варианта раскладки), **Мои записи** (+ сводка за месяц), **Дашборд** (5 виджетов), **Администрирование** (только роль `lead`).

## About the Design Files
Файлы в `prototype/` — **дизайн-референс, сделанный в HTML**: прототип, показывающий задуманный вид и поведение, а не продакшн-код для копирования. Задача — воспроизвести эти экраны в целевом окружении проекта (по ТЗ: **Vue 3 + PrimeVue + Tailwind**, бэкенд Fastify + Prisma + PostgreSQL), используя его собственные компоненты и практики. Разметка прототипа — инлайновые стили поверх CSS-переменных; в реальном проекте переменные из `tokens/themes.css` должны стать темой (PrimeVue preset / Tailwind theme), а вёрстка — компонентами.

`prototype/Clever Vibe.dc.html` открывается в браузере как есть (рядом лежит `support.js`, стили — `../tokens/nocturne-styles.css`). Иконки подключаются с CDN (@phosphor-icons/web), шрифт Inter — с Google Fonts.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, плотность, интерактив. Данные в прототипе моковые (генерируются в логике), API нет. Все агрегаты считаются на лету из массива записей.

## Themes
Три темы, все построены на одном наборе токенов; переключение — атрибутом `data-theme` на корне (в прототипе — селектор в шапке, значение хранится в `localStorage['aiTrackerTheme']`). Полные значения — `tokens/themes.css`.

| Тема | Режим | Ground | Акцент | Предупреждение | Ошибка/низкое доверие |
|---|---|---|---|---|---|
| `nocturne` (по умолчанию) | dark | #161826 / #232532 | #9184d9 (blurple) | #c6a377 | #c68e94 |
| `black` | dark | oklch(0.13 0 0) / oklch(0.19 0 0) | oklch(0.70 0.15 148) — зелёный | oklch(0.85 0.15 95) — жёлтый | oklch(0.65 0.20 27) — красный |
| `mint` | light | oklch(0.96 0.014 165) / oklch(0.995 0.005 165) | oklch(0.52 0.10 168) — зелёный | oklch(0.55 0.10 70) | oklch(0.52 0.13 22) |

Ключевые правила тем:
- Каждая роль (`neutral`, `accent`, `accent-2`) несёт шкалу 100–900 на одной перцептивной шкале светлоты: `[0.96, 0.91, 0.84, 0.74, 0.63, 0.52, 0.42, 0.32, 0.23]`; хрома акцента по шагам — базовая хрома × `[0.25, 0.4, 0.6, 0.85, 1, 0.9, 0.75, 0.55, 0.4]`.
- **В светлой теме шкала светлоты инвертируется** (шаг 800 остаётся «тихой границей», шаг 300 — читаемым текстом). Поэтому семантика использования шагов одна и та же во всех темах.
- `accent-2` — вторая «нота» того же акцента (в Nocturne это моно-схема): используется для шкалы **доверия**, тогда как `accent` — для **пользы**.
- Nocturne — это бандленная дизайн-система (`tokens/nocturne-styles.css`, гайд `tokens/nocturne-readme.md`): dark ground, Inter, радиус 8px, плотность 0.70×, иконки Phosphor.

## Design Tokens
Единые для всех тем (из Nocturne):
- Типографика: `--font-heading` / `--font-body` = Inter; заголовки weight 500, не жирнее. Размеры в интерфейсе: h1 21px, h2 14.5–15px, body 13px, вспомогательный 12–12.5px, микро-подписи 10.5–11.5px, лейблы секций 11px uppercase letter-spacing .09em.
- Числа — `font-variant-numeric: tabular-nums`.
- Spacing: `--space-1` 2.8 / `-2` 5.6 / `-3` 8.4 / `-4` 11.2 / `-6` 16.8 / `-8` 22.4 px.
- Radius: `--radius-sm` 4 / `--radius-md` 8 / `--radius-lg` 14 px.
- Elevation: `--shadow-sm/md/lg` (на тёмном фоне — граница + мягкая тень, не стопка теней).
- Семантические: `--warn` (мало данных, нулевое покрытие), `--warn-dim` (подписи «мало данных»), `--bad` (низкое доверие, ошибка входа).

Роли шагов, как они применены в дизайне:
| Использование | Токен |
|---|---|
| Фон страницы, инпуты, «вложенные» плашки | `--color-bg` |
| Карточки, панели, шапка | `--color-surface` |
| Границы карточек и контролов | `--color-neutral-800` |
| Границы инпутов и вторичных кнопок | `--color-neutral-700` |
| Разделители строк списков/таблиц | `--color-neutral-900` |
| Основной текст | `--color-text` |
| Вторичный текст | `--color-neutral-400` |
| Подписи, мета | `--color-neutral-500` |
| Приглушённые значения (N < 5) | `--color-neutral-600` |
| Акцентное действие: фон / рамка / текст | `--color-accent-900` / `--color-accent-700` / `--color-accent` |
| Графика дашборда (полосы, точки, линия) | `--color-accent` |
| Оценка «доверие» | `--color-accent-2-900/-700/-400` |

Состояния: `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px }`, `::selection` — `--color-accent-800`, disabled — opacity .45. Ховер вторичной кнопки: рамка `--color-accent-700`, текст `--color-accent`.

## Screens / Views

### 1. Вход
- **Назначение:** авторизация по логину и паролю. Полноценной аутентификации не требуется (4 человека, внутренний контур), но доступ выдаётся лидом при создании участника.
- **Layout:** карточка 360px по центру вьюпорта. Сверху точка-акцент 9px + «Clever Vibe», h1 «Вход», подпись «Логин и пароль выдаёт тимлид при создании участника». Карточка: `--color-surface`, рамка `--color-neutral-800`, `--radius-lg`, padding `--space-8`, поля в колонку с gap `--space-4`.
- **Компоненты:** два инпута (лейбл 11px uppercase; поле — фон `--color-bg`, рамка `--color-neutral-700`, `--radius-md`, padding `--space-3 --space-4`, 13px), пароль `type="password"`; строка ошибки — иконка `ph-warning` + текст `--bad`; кнопка «Войти» на всю ширину (активная: фон `--color-accent-900`, рамка `--color-accent-700`, текст `--color-accent`; неактивная: прозрачная, рамка `--color-neutral-800`, текст `--color-neutral-600`). Под карточкой — подпись с демо-доступами и селектор темы.
- **Поведение:** Enter отправляет форму; неверная пара — «Неверный логин или пароль»; деактивированный участник — «Участник деактивирован». Демо: `artem / lead-4821` (lead), `nikita / dev-7395`, `polina / dev-2064`, `daniil / dev-5178`.

### 2. Шапка (после входа)
Sticky, высота 58px, фон `color-mix(in srgb, var(--color-bg) 92%, transparent)` + `backdrop-filter: blur(10px)`, нижняя граница `--color-neutral-800`. Слева: точка-акцент со свечением, «Clever Vibe», бейдж «FE / Angular». Далее табы (активный — фон `--color-neutral-900`, текст `--color-text`). Справа: селектор темы (иконка `ph-palette`), имя + роль текущего пользователя, кнопка «Выйти» (`ph-sign-out`).

### 3. Быстрый ввод — главный экран
- **Назначение:** внести запись за 20–30 секунд. Всё на одном экране, без переходов и скролла на десктопе.
- **Три раскладки** (переключатель в заголовке; в проекте достаточно выбрать одну):
  - **A · Панель** — грид `minmax(0,1fr) 336px`: слева форма, справа «Последние 3 записи» и легенда шкал.
  - **B · Поток** — одна колонка 720px, шаги пронумерованы (1 Стадия → 2 Подход → 3 Польза → 4 Доверие), внизу строка «инструмент / задача / заметка / Сохранить», под карточкой три последние записи в ряд.
  - **C · Три колонки** — грид `230px minmax(0,1fr) 300px`: стадии списком, подходы списком, оценки и сохранение в правой колонке.
- **Компоненты:** чипсы стадий (padding `--space-2 --space-4`, `--radius-md`; выбранная — фон `--color-accent-900`, рамка `--color-accent-700`, текст `--color-accent`); чипсы подходов, отфильтрованные по стадии, последний чип — «Другой подход» (`ph-plus`) со свободным текстом в отдельное поле; селект инструмента (запоминает последний выбор пользователя); два ряда по 5 кнопок оценок с подписью текущего значения справа (польза — `accent`, доверие — `accent-2`); `taskRef` (опционально, tabular-nums, плейсхолдер FE-1042); заметка свёрнута по умолчанию (`ph-plus` / `ph-minus`); кнопка «Сохранить запись» + подсказка; «Очистить».
- **Поведение:** кнопка активна только при выбранных подходе, пользе и доверии (для «другого подхода» — ещё непустой текст). После сохранения форма очищается, **стадия и инструмент сохраняются**. Черновик формы пишется в `localStorage['aiTrackerDraft']` при каждом изменении и восстанавливается при загрузке; после сохранения — удаляется. Показываются последние 3 записи пользователя. Экран должен работать с телефона.

### 4. Мои записи
- **Layout:** грид `minmax(0,1fr) 400px`. Слева список с фильтрами (стадия, месяц/весь пилот) и счётчиком показанных; строка записи — грид `78px minmax(0,1fr) 120px 92px`: дата, подход + мета (стадия · инструмент · задача) + заметка (левая полоса `--color-neutral-700`), оценки, действия.
- **Компоненты:** «Изменить» / «Удалить» доступны 7 дней, дальше — «7 дней прошло». Удаление — только `deletedAt`, физического удаления нет.
- **Блок «Моя сводка за месяц»:** группировка стадия → подход → N, средняя польза, среднее доверие, своя заметка; при N < 5 строка приглушена и помечена «мало данных». Кнопка «Копировать текстом» кладёт сводку в буфер в виде плоского текста (стадия, N, строки подходов, заметки).

### 5. Дашборд (десктоп)
Грид первого ряда `minmax(0,1.35fr) minmax(0,1fr)`, второго — `minmax(0,1fr) minmax(0,1.45fr)`.
1. **Квадранты «частота × польза»** — область 340px, каждый подход — точка: X = число применений командой, Y = средняя польза, размер = число записей (10 + min(20, N×1.1) px), цвет = среднее доверие (< 2.6 → `--bad`, < 3.6 → `--warn`, иначе `--color-accent`; заливка — тот же цвет 40%). Границы квадрантов — **медианы** (не фиксированные значения), подписи в углах: продвигать / закрепить / отбросить / разбираться. Клик по точке → правая панель со всеми записями по подходу и заметками.
2. **Покрытие стадий** — строка `130px minmax(0,1fr) 84px`: название, полоса 9px (`--color-accent`; при N < 5 — `--warn`), «N n» + иконка `ph-warning` для почти пустых стадий.
3. **Динамика средней пользы** — по месяцам, суммарно или по выбранной стадии: линия (SVG polyline, stroke `--color-accent`, 2px), точки 8px, под осью — месяц, значение (приглушено при N < 5) и N.
4. **Разброс между участниками** — по подходу отрезок min–max средних оценок людей на шкале 1–5, справа «±дельта»; при разбросе ≥ 2 отрезок жёлтый. Подпись: большой разброс — дело в способе применения, повод для обмена практиками.
5. **Таблица подходов** — подход, стадия, N, польза, доверие, охват (`n/4`), флаг «мало данных»; сортировка кликом по любой колонке (индикатор — `ph-arrow-up`/`ph-arrow-down`), клик по строке → та же панель записей. Заголовок sticky, тело со скроллом (max-height 360px).

**Обязательное правило:** рядом со средней всегда N; при N < 5 значение выводится `--color-neutral-600` с пометкой «мало данных».

### 6. Администрирование (только `lead`)
- Для роли `dev` — плашка «экран доступен только лиду».
- **Кастомные подходы на разбор:** текст, автор/частота/период, кнопка «Промоутить» (после — «В справочнике», `isCustom = true`).
- **Справочник подходов:** фильтр по стадии, «+ Подход», строка `minmax(0,1fr) 110px 54px 96px`: название (+ бейдж `isCustom`), стадия, N, «Деактивировать»/«Включить».
- **Пользователи:** «+ Пользователь» → имя + роль (dev / lead) → «Создать». Система **сама выдаёт логин** (транслит имени, при коллизии — суффикс 2, 3, …) **и пароль** (8 символов из алфавита без похожих знаков). Выданные доступы показываются в акцентной плашке над списком с кнопкой «Скопировать» (`ph-copy`); логин виден в мете участника. Активация/деактивация участника — там же.
- **Экспорт CSV** (`ph-download-simple`): все поля записей — `id,userId,createdAt,stage,approach,customApproachText,taskRef,tool,usefulness,trust,note`.

## Interactions & Behavior
- Навигация — четыре таба, без роутинга в прототипе; в приложении это маршруты.
- Правая панель записей (drawer 520px) поверх затемнения `color-mix(in srgb, var(--color-bg) 78%, transparent)`; закрытие — клик по фону или `ph-x`.
- Тост подтверждения снизу по центру (2.2 с): сохранение записи, промоут подхода, создание участника, копирование, экспорт.
- Свободный ввод названия подхода запрещён: только справочник + «другой подход» в отдельное поле.
- Адаптивность: быстрый ввод обязан работать с телефона; дашборд — только десктоп.

## State Management
Состояние прототипа (в приложении разложить на стор/сервер):
- `authed`, `userId`, `loginForm {login, pass, error}`, `createdCreds {name, role, login, pass}`
- `screen`, `layout` (a|b|c), `theme` (`localStorage['aiTrackerTheme']`)
- `form {stage, approach, custom, tool, usefulness, trust, taskRef, note, noteOpen}` + черновик в `localStorage['aiTrackerDraft']`
- `entries[]` (в проекте — API), `inactive{}` (подходы), `inactiveUsers{}`, `promoted{}`
- фильтры: `mineStage`, `mineMonth`, `dynStage`, `adminStage`; сортировка `sortKey`/`sortDir`; `selected` (подход для панели), `toast`

## Расчёты
- Средняя польза подхода = среднее `usefulness` по всем его записям; среднее доверие = среднее `trust`.
- Частота = count записей; охват = count distinct `userId`.
- Медианы для границ квадрантов — по текущему набору подходов, имеющих хотя бы 1 запись.
- Все выводимые числа округляются до одного знака после запятой.
- Шкалы 1–5 (польза: помешало → сэкономило часы; доверие: выкинул полностью → взял как есть) — намеренно пятибалльные.
